# Token 速度与用量口径

速度反映模型请求的输出速率，不代表整个 Agent 完成任务的速度。

## 工具调用怎样计入

- 模型生成的工具名、参数属于模型输出，保留在输出 token 中。
- 工具执行、网络访问、命令运行和等待结果发生在模型请求之间，不加入速度分母。
- 工具结果作为后续请求的输入，不加入输出速度分子。
- 一轮包含多次请求时，均速 = 有效请求输出之和 ÷ 对应有效窗口之和；不使用整轮或整个会话的墙钟耗时。
- 并行子 Agent 仍按各自请求累加，这个均速不是所有 Agent 同时输出的总吞吐量。

例如：两次请求各输出 100 token，各生成 1 秒，中间工具运行 60 秒。均速为 200 ÷ 2 = 100 t/s，而不是 200 ÷ 62。

## 时间窗口与质量标记

| 来源 | 可用时间 | 展示口径 |
| --- | --- | --- |
| ZCode（含推理及 Claude 模型） | 首个非空正文或推理片段到请求完成 | 客户端观测流式速度；无首 token 时退回 ≈ 请求平均 |
| DSH | 日志中首末流式块之间的 duration_ms | 流式窗口速度，不再扣 TTFT |
| Kimi | 请求事件到用量事件；会话 HUD 有 step 流式遥测时优先使用它 | ≈ 请求平均，或可用遥测的流式速度 |
| Claude Code | 原始记录有 durationMs 才计算 | ≈ 请求平均 |
| OpenCode / MiniMax Code | 原始请求耗时 | ≈ 请求平均 |
| Codex / Cursor | 当前导入格式没有可靠请求耗时 | 不提供速度 |

首 token 时间仍可能受到供应商缓冲影响，流式窗口速度不是硬件解码基准。没有可信的推理起点时不通过回归斜率猜测供应商行为，也不把近似窗口标成精确生成速度。

有效样本要求输出大于 0、时间顺序有效、窗口在 200ms 到 1 小时之间；有完成状态时只接收完成/成功记录。窗口越界整体排除，不补成 1 秒，也不使用固定速度上限裁剪。前端只展示后端结果，空值保持不可用。

主窗口、项目会话、注入、HUD、模型速度页以及模型名称合并统一选池：存在可信流式样本时，均速/极值/分位数/样本数仅来自流式池；没有流式样本时才使用请求平均池，显示 ≈。两个池不混算；最近速度的时间和质量也必须属于所选模型样本池。单请求日志仍显示该请求自身的有效口径。

均速累加同一批样本的输出和时长；P10/P50/P90 是单请求速率分布。最近速度、均速和最快值含义不同。没有有效样本显示“—”。近似质量在注入条、悬浮窗和模型名称合并后继续保留。

## Token 和缓存

输出中已经包含的推理 token 不能重复相加。总量采用来源的 computed_total_tokens。

Claude/Kimi 输入不含缓存读写，输入侧总量为普通输入 + 缓存读 + 缓存写；其他已归一化来源的输入包含缓存。缓存不能在两种口径中统一扣减。悬浮窗对不单独显示的缓存写并入输入，保证总量完整。

费用按照原始来源区分输入口径，缓存读单独计价。原始记录提供缓存写量时使用可选 cache_write 价格；缺少专门价格时按普通输入价估算。旧版价格文件继续兼容。未提供缓存写明细的旧聚合不能用于还原精确的缓存写账单；这些费用始终是按配置价格折算的估算值。

## 验证

- Rust：请求时间校验、DSH 不重复扣首字、非完成状态拒收、缓存口径与费用、会话/模型聚合。
- 工具等待回归：请求间 60 秒工具执行不影响 100 t/s 的计算结果。
- `npm run test:speed`：前端不复活被拒样本、近似标记保留、真实时长权重、缓存费用一致性。
- `npm run build`：前端类型检查与生产构建。
- 本机只读验收：`cargo test --lib local_speed_readonly_audit -- --ignored --nocapture`（在 src-tauri 目录执行）。读取各来源现有数据库，独立复算分组均速、样本数与质量标记；仅打印来源及计数，不打印对话或凭据。无计时的来源必须保持速度不可用。
